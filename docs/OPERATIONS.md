# Pushover operations

> Build, deploy, verify, and connect clients to the Pushover MCP server.
> For the HTTP authentication design, see [ARCHITECTURE.md](ARCHITECTURE.md).

## Configuration

The following table covers every application environment variable read by the current code.
Configuration loading and defaults are in `config.go:95-142` and `config.go:157-241`.
Logging reads `PUSHOVER_LOG_LEVEL` in `logging.go:9-29`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `APP_KEY` | none; required | Pushover application key. |
| `RECIPIENT_KEY` | none; required | Pushover user or group key. |
| `DEVICE_NAME` | empty | Default target device. |
| `DEFAULT_TITLE` | empty | Title used when no title is supplied. |
| `PUSHOVER_PRIORITY` | `-1` | Default notification priority. |
| `PUSHOVER_SOUND` | `vibrate` | Default notification sound. |
| `PUSHOVER_EXPIRE` | `180s` | Default emergency expiry. |
| `PUSHOVER_RETRY` | `60s` | Default emergency retry interval. |
| `PUSHOVER_HTTP_ADDRESS` | `127.0.0.1:8080` | HTTP listen address. |
| `PUSHOVER_HTTP_PATH` | `/mcp` | Streamable HTTP MCP endpoint path. |
| `PUSHOVER_HTTP_STATELESS` | `false` | Enable stateless streamable HTTP sessions. |
| `PUSHOVER_HTTP_HEARTBEAT` | `30s` | Streamable HTTP heartbeat interval. |
| `PUSHOVER_HTTP_TIMEOUT` | `30s` | HTTP read and write timeout. |
| `PUSHOVER_HTTP_CORS_ENABLED` | `true` | Add CORS middleware. |
| `PUSHOVER_HTTP_CORS_ORIGINS` | empty | Comma-separated allowed origins; empty allows none. |
| `PUSHOVER_HTTP_DISABLE_LOCALHOST_PROTECTION` | `true` | Disable mcp-go DNS-rebinding protection for the reverse proxy. |
| `PUSHOVER_AUTH_ENABLED` | `false` | Require bearer authentication for the HTTP MCP endpoint. |
| `PUSHOVER_AUTH_SECRET_KEY` | none | HS256 signing secret; required when HTTP authentication is enabled. |
| `PUSHOVER_MCP_OAUTH` | `false` | Enable the OAuth server and HTTP protection. |
| `PUSHOVER_MCP_ISSUER` | none | Public OAuth issuer URL. |
| `PUSHOVER_MCP_RESOURCE` | none | Public OAuth protected-resource URL. |
| `PUSHOVER_MCP_LOGIN_USER` | none | OAuth login username. |
| `PUSHOVER_MCP_LOGIN_PASSWORD_HASH` | none | Hash generated by `-hash-password`. |
| `PUSHOVER_MCP_ACCESS_TTL` | `1h` | OAuth access-token lifetime. |
| `PUSHOVER_MCP_REFRESH_TTL` | `720h` | OAuth refresh-token lifetime. |
| `PUSHOVER_LOG_LEVEL` | `info` | JSON log threshold: `debug`, `info`, `warn`, or `error`. |

When OAuth is enabled, it enables HTTP authentication and requires a signing secret of at least 32 bytes (`config.go:215-217`, `config.go:265-275`).
OAuth also validates the issuer, resource, login user, password hash, and token lifetimes at startup (`config.go:281-292`, `internal/oauth/config.go:25-63`).
A malformed value in any `PUSHOVER_*` variable, such as `PUSHOVER_PRIORITY=high` or `PUSHOVER_RETRY=soon`, stops startup with the variable name and the value;
an explicit `PUSHOVER_EXPIRE` or `PUSHOVER_RETRY` is taken as given and range-checked, not replaced by a default (`config.go:111-142`, `config.go:319-361`).

## Build

Build the deployed binary with:

```sh
task build
```

The build task re-runs when its Go sources, `go.mod`, `go.sum`, or the
`git describe --tags --always --dirty` version changes, and is otherwise skipped
as up to date (`Taskfile.yml:30-47`). The output is `bin/pushover`
(`Taskfile.yml:7-8`, `Taskfile.yml:30-47`).

## VPS environment and systemd

Production uses `/etc/systemd/system/pushover.service` with `/home/debian/Go/src/Pushover` as its working directory.
Production currently sets `PUSHOVER_HTTP_ADDRESS=:8092` behind nginx.
For a new or revised unit, prefer `127.0.0.1:8092` so the server is not reachable except through nginx.
The checked-in nginx configuration expects that loopback upstream (`deploy/nginx-pushover.conf:11-12`, `deploy/nginx-pushover.conf:47-52`).

Use placeholders only for credentials:

```ini
[Unit]
Description=Pushover MCP server
After=network-online.target

[Service]
User=debian
WorkingDirectory=/home/debian/Go/src/Pushover
ExecStart=/home/debian/Go/src/Pushover/bin/pushover mcp -transport http
Restart=on-failure
StandardOutput=append:/var/log/Pushover.log
StandardError=append:/var/log/Pushover.log
Environment=APP_KEY=<pushover-application-key>
Environment=RECIPIENT_KEY=<pushover-recipient-or-group-key>
Environment=PUSHOVER_HTTP_ADDRESS=127.0.0.1:8092
Environment=PUSHOVER_HTTP_STATELESS=true
Environment=PUSHOVER_MCP_OAUTH=true
Environment=PUSHOVER_MCP_ISSUER=https://karma.rrj.pl/pushover
Environment=PUSHOVER_MCP_RESOURCE=https://karma.rrj.pl/pushover/mcp
Environment=PUSHOVER_MCP_LOGIN_USER=<oauth-login-user>
Environment=PUSHOVER_MCP_LOGIN_PASSWORD_HASH=<generated-password-hash>
Environment=PUSHOVER_AUTH_SECRET_KEY=<at-least-32-random-bytes>

[Install]
WantedBy=multi-user.target
```

`-transport http` selects the HTTP server; STDIO is the default transport (`mcp_cli.go:67-76`, `mcp_server.go:152-164`).
Generate the login hash interactively, then place stdout in `PUSHOVER_MCP_LOGIN_PASSWORD_HASH`:

```sh
bin/pushover mcp -hash-password
```

The program blank-imports `godotenv/autoload` (`main.go:3-9`).
That package calls `godotenv.Load`, which reads `.env` from the working directory and does not replace an already-set environment variable.
Systemd `Environment=` values therefore take precedence over `.env` values.

After editing the unit, reload its definition before restarting it:

```sh
sudo systemctl daemon-reload
sudo systemctl restart pushover
sudo systemctl status pushover --no-pager
```

## OAuth discovery paths

`ProtectedResourceMetadataPath` appends the resource path to `/.well-known/oauth-protected-resource`.
`authorizationServerMetadataPath` appends the issuer path to `/.well-known/oauth-authorization-server` (`internal/oauth/oauth_metadata.go:92-118`).
`Mount` registers both derived paths and their bare compatibility paths (`internal/oauth/mount.go:17-30`).

For the production issuer and resource, the required paths are:

- `/.well-known/oauth-protected-resource/pushover/mcp`
- `/.well-known/oauth-authorization-server/pushover`

## nginx

Install the three blocks in [deploy/nginx-pushover.conf](../deploy/nginx-pushover.conf) inside karma's TLS server block.
Do not include Pushover in the shared `location ~ ^/(?:answer|gemini|time|...)/` alternation or its backend map.
That location denies GET, but OAuth browser authorization requires `GET /authorize` (`deploy/nginx-pushover.conf:4-9`, `internal/oauth/oauth_authorize.go:48-54`).
The exact-match well-known locations preserve discovery paths, and the trailing slash on the service `proxy_pass` removes `/pushover/` before forwarding (`deploy/nginx-pushover.conf:22-47`).

Validate nginx before reloading it:

```sh
sudo nginx -t && sudo systemctl reload nginx
```

## Verification

With the production service and nginx configuration active, run these from a trusted shell:

```sh
curl -si -X POST https://karma.rrj.pl/pushover/mcp
curl -fsS -o /dev/null -w '%{http_code}\n' \
  https://karma.rrj.pl/.well-known/oauth-protected-resource/pushover/mcp
curl -fsS -o /dev/null -w '%{http_code}\n' \
  https://karma.rrj.pl/.well-known/oauth-authorization-server/pushover
curl -fsS -o /dev/null -w '%{http_code}\n' https://karma.rrj.pl/pushover/health
curl -fsS -o /dev/null -w '%{http_code}\n' https://karma.rrj.pl/pushover/capabilities
```

The first command must return HTTP 401 with `WWW-Authenticate` containing `resource_metadata` when OAuth is enabled (`auth.go:121-150`, `auth.go:163-176`).
The two discovery commands, health, and capabilities must return HTTP 200.
The mux registers the health and capabilities routes outside the MCP guard (`http_server.go:56-65`, `http_server.go:111-144`).

## Connect from Claude

### Claude.ai, Desktop, and mobile

These clients use the connector flow.
Add a custom connector with URL `https://karma.rrj.pl/pushover/mcp`.
Leave Client ID and Client Secret empty so the server can dynamically register the client through `/register` (`internal/oauth/mount.go:27-30`, `internal/oauth/oauth_clients.go:347-389`).
Complete the browser login with the configured OAuth login user and password.
The claude.ai connector was verified on 2026-10-17 by logging in and calling `send_notification`.

### Claude Code

Add a project `.mcp.json` entry without headers to start the OAuth login flow:

```json
{
  "mcpServers": {
    "pushover": {
      "type": "http",
      "url": "https://karma.rrj.pl/pushover/mcp"
    }
  }
}
```

Run `/mcp` in Claude Code to open the OAuth login.
As an alternative for scripts or existing Trading configuration, generate a static token:

```sh
bin/pushover mcp -generate-token -token-username <user> -token-ttl <duration>
```

`-token-username` defaults to `admin`, and `-token-ttl` is a Go duration that defaults to `744h` (`mcp_cli.go:73-99`).
It prints a static bearer token and requires only `PUSHOVER_AUTH_SECRET_KEY` (`mcp_cli.go:88-98`).
Configure it as a header instead of using the OAuth-only entry:

```json
{
  "mcpServers": {
    "pushover": {
      "type": "http",
      "url": "https://karma.rrj.pl/pushover/mcp",
      "headers": {
        "Authorization": "Bearer <token from -generate-token>"
      }
    }
  }
}
```

For a Claude Code “Conflicting scopes” error, remove the stale local entry and run `/mcp` again:

```sh
claude mcp remove pushover -s local
```

## Troubleshooting

- A missing closing quote in a systemd `Environment=` line silently drops that variable.
- Run `systemctl daemon-reload` after every unit-file edit and before restart.
- OAuth configuration failures stop startup with an error that identifies the invalid or absent value (`config.go:244-292`, `internal/oauth/config.go:25-63`).
- Leave `PUSHOVER_HTTP_DISABLE_LOCALHOST_PROTECTION=true` behind the supplied nginx proxy.
  Its default is true because mcp-go would otherwise reject the forwarded public `Host` header as a DNS-rebinding risk (`config.go:102`, `config.go:181`, `http_server.go:42-45`).
- OAuth state is in memory, so restart loses refresh state and eventually requires a new login.
  See [OPEN_ITEMS.md](OPEN_ITEMS.md#debt) for the access-token caveat.
